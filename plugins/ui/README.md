# ui

[frontend-design](https://github.com/anthropics/claude-plugins-official) 스킬을 기반으로, 레퍼런스를 반영하고 분야에 맞춰 최적화한 UI/UX를 디자인합니다. **코드보다 목업 이미지가 먼저**입니다. 리서치 에이전트가 실제 제품·최근 트렌드·컬러 레퍼런스를 찾아 정리한 근거로 목업을 만들고, 시니어 UI/UX 리뷰 에이전트가 리뷰하고 고친 목업을 사용자가 승인하면 그것을 구현합니다.

## 0.2.0에서 바뀐 점

- 목업을 만들기 전에 `ui:researcher`가 같은 분야의 실제 제품, 최근 12개월의 트렌드, 컬러 레퍼런스를 웹에서 찾아 직접 열어 보고 `.design/research/`에 정리합니다
- `ui:reviewer`가 목업을 심각도별로 리뷰하고(`.design/reviews/`), 고친 다음 버전을 만든 뒤에 사용자 승인을 받습니다
- `render-mockup.sh`가 로컬 HTML뿐 아니라 레퍼런스 사이트 URL도 캡처합니다

## 설치

```
/plugin marketplace add LimjeongSik/baton-workflow
/plugin install ui@baton
```

`frontend-design@claude-plugins-official`이 의존성으로 함께 설치됩니다.

## 사용법

```
/ui:design 정비 기사용 작업 지시 대시보드 [레퍼런스 이미지 경로나 URL]
```

"이 레퍼런스처럼 랜딩 페이지 디자인해줘"처럼 자연어로 요청해도 됩니다.

## 흐름

1. frontend-design 스킬 호출 (필수)
2. 분야 판별(대시보드 / 모바일 앱 / 웹 앱 / 랜딩 / 커머스 / 콘텐츠)과 기존 디자인 시스템 확인
3. **리서치와 첫 목업 (`ui:researcher`):** 같은 분야에서 실제로 운영 중인 제품, 최근 12개월의 UI/UX 트렌드, 컬러 레퍼런스를 웹에서 찾아 직접 열어 보거나 캡처해서 `.design/research/<화면>.md`에 정리합니다. 트렌드는 AI 티 점검표로 걸러 쓸지 말지 판정합니다. 이 정리를 근거로 디자인 계획을 세우고, 팔레트 검사와 AI 티 점검을 거쳐 목업 v1을 만듭니다
4. **시니어 리뷰와 개선 (`ui:reviewer`):** 목업 PNG를 보고 과업·위계·리듬·타이포·컬러·상태·접근성·카피를 리뷰해 심각도별로 지적하고(`.design/reviews/`), 지적을 반영한 v2를 만들어 v1과 비교해 확인합니다
5. **사용자 승인** (이대로 / 수정 후 다시 / 다른 방향). v1과 v2를 함께 보여줍니다
6. 승인된 목업 기준으로 구현 → 스크린샷 비교 자기비평 → 보고

리서치는 사용자가 준 레퍼런스가 정하지 않은 부분을 채웁니다. 기존 디자인 시스템이 있으면 팔레트는 그대로 두고 레이아웃·밀도·위계를 리서치합니다. 서브에이전트 안에서 실행돼 에이전트를 띄울 수 없으면 두 역할을 순서대로 직접 합니다.

## 컬러 정책

새 디자인 시스템을 잡을 때는 밝은 면을 기본으로 합니다. 근거 없는 다크·네이비·인디고·보라 그라데이션, Tailwind 기본 팔레트, 크림·테라코타는 피합니다. 기존 디자인 시스템이나 레퍼런스가 정한 방향이 있으면 그것을 따릅니다.

## 타이포와 한국어 카피

모든 텍스트 스타일에 자간·행간을 직접 정하고(제목은 좁게, 한글 본문은 넉넉하게) 목업에서 눈으로 보고 조정합니다. 화면의 한국어는 번역투("~를 통해", "당신의", "더 알아보기"), 섞인 말투, 노출된 "을(를)" 없이 처음부터 한국어로 쓴 것처럼 씁니다.

## 목업 렌더링

Playwright(프로젝트 설치본 → 최신 버전) → 로컬 Chrome 계열 브라우저 순으로 찾습니다. 같은 스크립트로 레퍼런스 사이트 URL도 캡처합니다. 처음 실행할 때 Playwright 헤드리스 브라우저를 내려받을 수 있습니다.

만든 이미지와 문서는 모두 프로젝트 루트의 `.design/` 폴더에 저장됩니다. 리서치 문서와 레퍼런스 캡처는 `.design/research/`, 리뷰는 `.design/reviews/`, 목업은 `.design/mockups/`, 구현 후 스크린샷은 `.design/screenshots/`에 들어가며, 승인을 받을 때와 보고할 때 이 폴더를 열어 확인하라고 안내합니다. 커밋하지 않으려면 `.design/`을 `.gitignore`에 추가하세요.
