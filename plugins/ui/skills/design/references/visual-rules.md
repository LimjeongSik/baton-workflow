# 시각 규칙: 컬러·자간과 행간·한국어 카피

ui:design 3단계(디자인 계획)와 4단계(목업 자체 점검)에서 읽는다. 기존 디자인 시스템이나 레퍼런스가 정한 값이 있으면 그것이 우선한다.

## 컬러 정책 (기존 시스템이나 레퍼런스가 따로 정하지 않았을 때)

- **기본은 밝은 면이다.** 다크 테마는 사용자가 요청했거나, 그 분야의 실제 관례일 때만 쓴다. 영상·사진 편집 도구, 트레이딩 터미널, 야간 관제, 극장·공연 콘텐츠 등이 그런 분야다.
- **피할 기본값:**
  - 네이비·슬레이트 계열 배경 (`#0F172A`, `#1E293B`, `#111827`, `#0B1120` 근처)
  - 인디고·보라 강조와 보라→파랑 그라데이션 (`#6366F1`, `#8B5CF6`, `#7C3AED` 근처)
  - 다크 배경에 형광 글로우, 글래스모피즘
  - Tailwind 기본 팔레트를 그대로 쓴 조합 (`slate`/`gray`/`zinc` + `blue-500`/`indigo-600`)
  - frontend-design이 꼽은 크림+테라코타(`#F4F1EA`/`#D97757` 근처), 검정+형광 초록·주홍
- **중립색에도 성격을 준다.** 회색은 순수 회색이나 파란 슬레이트 대신 주조색 쪽으로 아주 살짝 기울인다.
- **강조색은 면적을 작게 쓴다.** 강조색이 의미(주요 행동, 상태, 선택)를 가질 때만 칠한다.
- **데이터 색은 브랜드 색과 따로 설계한다.** 차트 범주색은 구분이 잘 되고 색각 이상에서도 읽히게 하며, 상태색(성공·경고·오류)은 주조색과 겹치지 않게 한다.
- 텍스트 대비는 WCAG AA 이상을 지킨다 (본문 4.5:1, 큰 글자·UI 요소 3:1).

## 자간과 행간

서체를 고르는 것으로 끝내지 않는다. **모든 텍스트 스타일에 자간(`letter-spacing`)과 행간(`line-height`)을 직접 정한다.** 브라우저 기본값(`normal`)에 맡기지 않는다. 계획의 타입 항목에 크기·굵기와 함께 자간·행간을 적는다.

- **행간:** 글자가 클수록 좁히고, 작고 긴 글일수록 넓힌다. 한글은 같은 크기의 라틴 글자보다 글자 면이 꽉 차서 행간을 조금 더 줘야 답답하지 않다.
  - 큰 제목: 1.2~1.35
  - 본문(여러 줄): 1.6~1.75
  - 한 줄짜리 UI 텍스트(버튼, 라벨, 표 셀): 1.3~1.5. 고정 높이 요소 안에서는 세로 가운데가 맞는지 본다.
- **자간:** 크기에 반비례하게 잡는다. 단위는 `em`으로 써서 크기가 바뀌어도 비율이 유지되게 한다.
  - 큰 제목(32px 이상): `-0.02em`~`-0.03em` 정도로 줄인다. 한글 산세리프(Pretendard, 본고딕 등)는 큰 크기에서 자간이 벌어져 보인다.
  - 본문: `0`~`-0.01em`. 본문을 크게 줄이면 읽기가 느려진다.
  - 작은 글자(12px 이하)와 숫자 표: `0` 이상. 작은 글자를 줄이면 글자끼리 붙는다.
- 수치는 출발점이다. 서체마다 기본 자간과 글자 면이 다르므로 **렌더링한 목업에서 직접 보고 조정한다.** 레퍼런스가 있으면 레퍼런스의 자간·행간 감각을 먼저 따른다.
- 정한 값은 토큰으로 둔다 (예: `--leading-body`, `--tracking-heading`). 컴포넌트마다 다른 값을 흩뿌리지 않는다.

## 한국어 카피

화면에 들어가는 한국어는 **처음부터 한국어로 쓴 것처럼** 읽혀야 한다. 영어 UI를 옮긴 듯한 문장, 사람이 실제로 하지 않는 말은 쓰지 않는다. 카피를 확정하기 전에 소리 내어 읽어 보고, 이 제품의 실제 사용자가 이렇게 말하는지 확인한다.

- **번역투를 쓰지 않는다:**
  - "~를 통해", "~에 대한", "~을 진행하다", "~하는 것이 가능합니다", "~되어지다"
  - "당신의", "귀하의" 같은 2인칭 (한국어 UI는 주어를 생략하는 게 자연스럽다)
  - 영어 구조를 그대로 옮긴 말: "더 알아보기", "지금 시작하세요!", "~와 함께하세요", "당신만을 위한"
- **말투를 하나로 맞춘다.** 한 화면 안에서 "~합니다"와 "~해요"를 섞지 않는다. 버튼·메뉴는 명사형("저장")이나 동사형("저장하기") 중 하나로 통일한다.
- **명사만 늘어놓지 않는다.** "데이터 분석 결과 확인 기능"보다 "분석 결과 보기"처럼 짧고 동작이 보이게 쓴다.
- **외래어·영어는 그 분야 사용자가 실제로 쓰는 말만 쓴다.** 한국어로 충분한 자리에 영어를 섞지 않는다.
- **조사가 변수에 따라 바뀌는 자리를 처리한다.** 이름·항목명이 들어가는 문장에 "을(를)"을 그대로 노출하지 않는다. 받침에 따라 조사를 고르거나, 조사가 필요 없게 문장을 바꾼다.
- **띄어쓰기·맞춤법과 표기를 지킨다.** 숫자는 천 단위 쉼표, 단위는 붙여 쓰고("3개", "1,200원"), 날짜·시간 형식을 한 화면 안에서 통일한다.
- 문장 부호를 남발하지 않는다. 느낌표, 물결표, 말줄임표는 그 제품의 말투일 때만 쓴다.
