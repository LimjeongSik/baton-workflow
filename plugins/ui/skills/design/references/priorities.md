# 판단 우선순위

`ui:design` 본문, `ui:researcher`, `ui:reviewer`가 같은 기준으로 판단하도록 한 곳에 둔다. 지침끼리 부딪히면 이 문서를 따른다.

## 1. 사용자의 명시적 요청이 가장 앞선다

이번 요청에서 사용자가 직접 정한 것(색, 서체, 테마, 레이아웃, "이 레퍼런스처럼")은 아래 어떤 규칙보다 앞선다. 단, "이 레퍼런스처럼"은 레퍼런스의 리듬·밀도·톤을 따르라는 뜻이지, 기존 디자인 시스템을 바꾸라는 뜻이 아니다. 시스템을 바꾸라는 말이 따로 있어야 바꾼다.

## 2. 기존 디자인 시스템이 있는 프로젝트

- **기존 시스템이 기본이다.** 팔레트, 타입 스케일, 모서리 반경 체계, 간격 단위, 컴포넌트는 그대로 쓴다.
- **레퍼런스와 리서치는 시스템과 충돌하지 않는 축에 반영한다:** 레이아웃, 정보 밀도, 위계, 여백 리듬, 상태 표현, 카피 톤, 한 곳의 강조를 어디에 둘지.
- 레퍼런스나 선호 프로필이 시스템과 다른 방향이면(예: 시스템은 밝은 테마인데 레퍼런스는 다크) **시스템을 따르고**, 차이와 "바꾸면 무엇이 좋아지는지"를 제안으로만 따로 적는다.
- 시스템을 바꾸는 것(새 색 추가, 타입 스케일 변경, 테마 전환)은 사용자가 명시적으로 요청했을 때만 한다.
- 시스템 자체가 이 스킬의 컬러 정책에 어긋나도(예: 네이비 다크 테마) 임의로 바꾸지 않는다. 대비 미달처럼 실제 사용성 문제는 근거와 함께 보고한다.

## 3. 새로 디자인 시스템을 잡는 경우

기존 시스템이 없거나 사용자가 새로 잡아 달라고 했을 때만 해당한다. 위에서부터 앞선다:

1. 사용자가 준 레퍼런스: 사용자가 직접 고른 방향이다. 이 스킬의 컬러 정책과 달라도(예: 다크 테마) 레퍼런스를 따른다
2. 선호 프로필(`learn/learned.md`)의 `[확정]` 항목
3. 리서치 결과: 레퍼런스와 프로필이 정하지 않은 축을 채운다
4. 이 스킬의 기준(`visual-rules.md`의 컬러 정책, `domains.md`, `anti-ai-checklist.md`)
5. 선호 프로필의 `[추정]` 항목: 다른 근거가 없을 때만 따르고, 따랐으면 보고에 밝힌다
6. frontend-design 스킬의 원칙

## 4. 어느 경우든 지키는 바닥선

다음은 우선순위와 관계없이 지킨다. 지킬 수 없으면 그 사실을 보고한다.

- 텍스트와 UI 요소 대비 WCAG AA (`palette-check.mjs`의 대비 실패는 고친다)
- 색만으로 상태를 구분하지 않기, 터치 타깃, 키보드 포커스
- 레퍼런스의 로고·고유 그래픽·브랜드 카피를 복제하지 않기
