# CLAUDE.md 양식

Claude Code는 루트 CLAUDE.md를 세션마다 읽고, 하위 폴더의 CLAUDE.md는 그 폴더의 파일을 읽을 때 불러온다. 그래서 **루트는 모든 작업에 필요한 것만**, 하위는 **그 폴더에서 작업할 때만 필요한 것**을 담는다.

## 루트 CLAUDE.md

목표는 60줄 안이다. 넘치면 폴더 전용 내용을 하위로 내린다.

```markdown
# <프로젝트명>

<무엇을 하는 프로젝트인지 한 줄>. <스택 한 줄: 예) Next.js 16 App Router · TypeScript · Tailwind v4 · TanStack Query>

## 명령
- 개발: `<pm> dev`
- 검사: `<pm> lint && <pm> typecheck`
- 테스트: `<pm> test`

## 규칙
- <references/conventions.md에서 조건에 맞는 규칙>
- <프로젝트 전체에 걸친 규칙이 더 있으면 여기에. 폴더 하나에만 해당하면 하위로>

## 하위 CLAUDE.md (폴더가 생기면 추가)
폴더를 새로 만들거나 폴더의 계약·흐름을 바꾸면, 그 폴더의 CLAUDE.md와 이 목록을 같은 작업 안에서 갱신한다.
- `src/lib/CLAUDE.md` — <그 문서가 다루는 주제를 쉼표로 3~6개>
- `src/app/api/CLAUDE.md` — <...>
```

목록 위의 유지 규칙 한 줄은 지우지 않는다. 이 줄이 있으면 `/context:sync`를 다시 실행하지 않아도 Claude가 평소 작업 중에 문서를 맞춘다.

- **명령:** `package.json` 스크립트에 실제로 있는 것만 적는다. 없으면 그 줄을 뺀다.
- **하위 목록:** 경로는 저장소 루트 기준으로 백틱 안에 쓴다. `scan.mjs`가 이 형식(`` `경로/CLAUDE.md` ``)으로 목록을 읽어 실제 파일과 대조한다. 형식을 바꾸지 않는다.
- 요약은 "무엇이 들어 있는지"를 명사구로 쓴다. 예: `JWT 세션, DAL, next 경로 검증, 2단 보호`.
- 경로 순서는 상위 폴더가 먼저, 같은 깊이는 알파벳순이다.

## 하위 CLAUDE.md

목표는 40줄 안이다. 절은 내용이 있는 것만 둔다.

```markdown
# <폴더 경로> — <역할 한 줄>

## 구조
- `client.ts` — <책임 한 줄>
- `_lib/` — <책임 한 줄>

## 규칙
- <이 폴더에서만 지키는 규칙. 예: Route Handler는 handleRoute로만 감싼다. 요청 스키마는 같은 폴더 schema.ts에 둔다>

## 계약·흐름
- <다른 폴더가 기대는 인터페이스, 데이터가 흐르는 순서, 좌표계·단위·시간대처럼 틀리기 쉬운 전제>

## 하지 않을 것
- <이 폴더에서 자주 틀리는 것. 예: 서버 전용 apiServer를 클라이언트 컴포넌트에서 import하지 않는다>
```

## 무엇을 적고 무엇을 빼는가

**적는다** (코드만 봐서는 알기 어렵거나 틀리기 쉬운 것):
- 여러 파일에 걸친 계약과 데이터 흐름
- 이 폴더에서만 쓰는 패턴과 그 이유
- 단위·좌표계·시간대·정렬 기준 같은 전제
- 서버 전용과 클라이언트 전용의 경계, 보안상 지켜야 하는 경계
- 상태의 단일 출처 (예: "필터 상태는 URL이 단일 출처")

**뺀다:**
- 파일 목록 전체. 구조 절에는 역할이 자명하지 않은 것만
- 함수 시그니처나 코드 복사. 코드가 바뀌면 바로 틀린 문서가 된다
- 루트에 이미 있는 규칙의 반복
- 진행 상황과 할 일. 그건 진행 문서(`docs/PROGRESS.md`)의 몫이다
- 확인하지 않은 추측
