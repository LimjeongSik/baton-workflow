# CLAUDE.md 구성 맞추기

CLAUDE.md는 **Claude가 작업 전에 읽는 규칙 문서**다. 루트 문서는 모든 세션에서 읽히므로 짧게 유지한다. 폴더 전용 내용은 그 폴더의 CLAUDE.md로 내린다. Claude Code는 하위 폴더의 CLAUDE.md를 그 폴더 파일을 읽을 때 불러온다.

- 인자 없음: 저장소 전체를 맞춘다. 루트가 없으면 만들고, 있으면 고친다.
- 폴더 경로를 받으면 그 폴더의 하위 CLAUDE.md만 만들거나 고치고, 루트 목록을 갱신한다.

양식은 `references/templates.md`, 기본 규칙은 `references/conventions.md`에 있다. 쓰기 전에 둘 다 읽는다.

## 1. 사실 수집

```bash
node "${CLAUDE_SKILL_DIR}/scripts/scan.mjs"
```

출력되는 JSON의 내용:
- `stack`: Tailwind 사용 여부와 버전, TypeScript, 프레임워크, 플랫폼(`platform`: `react-native`·`expo`가 있으면 `"app"`, 웹 프레임워크만 있으면 `"web"`), 상태·네트워크·내비게이션 라이브러리(`libs`), import 별칭(`aliases`), `src/` 유무, 테스트 배치, 파일명 관례 표본(`naming`), 패키지 매니저와 검사 스크립트
- `claudeMd`: 기존 CLAUDE.md 목록, 루트 목록에 있는데 파일이 없는 것(`dangling`), 파일은 있는데 목록에 없는 것(`unlisted`), `AGENTS.md`
- `candidates`: 소스 파일이 일정 수(기본 5개) 이상인 폴더와 CLAUDE.md 유무. `_components` 같은 전용 하위 폴더와 `__tests__`는 부모 폴더에 합산된다

`AGENTS.md`가 있으면 읽는다. 내용이 겹치면 한쪽에만 두고, 다른 쪽에서는 그 문서를 가리킨다.

## 2. 루트 CLAUDE.md

**없으면** 양식대로 만든다. **있으면** 기존 내용을 지우지 않고 아래만 맞춘다:

1. **명령:** `stack.scripts`와 `packageManager`로 실제 명령을 적는다. 없는 스크립트는 적지 않는다.
2. **규칙:** `conventions.md`에서 조건에 맞는 규칙만 넣는다. 특히 다음을 지킨다.
   - Tailwind 규칙은 `stack.tailwind.used`가 true일 때만 넣는다. 토큰 예시는 프로젝트의 실제 토큰으로 바꾼다.
   - React·React Native 프로젝트에는 훅 규칙을 넣는다. `useState`를 남발하지 않고(파생 값은 렌더 중 계산), `useEffect`는 외부 시스템 동기화에만 쓰고, 의존성 배열과 정리 함수를 빠뜨리지 않게 한다.
   - `stack.platform`에 맞는 웹 규칙이나 앱 규칙을 넣는다. 아래 "플랫폼별 초점"을 기준으로 한다.
   - 기존 코드가 기본값과 다른 관례를 일관되게 쓰면 그 관례를 적는다. 관례가 섞여 있으면 기본값을 적고, 기존 파일 이름은 바꾸지 않는다고 한 줄 덧붙인다.
   - 기존 루트에 같은 주제의 규칙이 있으면 사용자가 쓴 쪽을 남긴다. 기본값과 충돌하면 고치지 말고 보고에 적는다.
3. **하위 목록:** `## 하위 CLAUDE.md (폴더가 생기면 추가)` 절을 둔다. 실제로 있는 하위 CLAUDE.md만 적는다. `dangling`은 지우고, `unlisted`는 그 파일을 읽어 요약과 함께 추가한다.
4. **내리기:** 루트에 특정 폴더에서만 의미 있는 내용(특정 API 규칙, 특정 화면의 데이터 흐름 등)이 있으면 그 폴더의 하위 CLAUDE.md로 옮긴다. 옮긴 내용은 루트에서 지운다.

루트는 60줄 안을 목표로 한다.

## 3. 하위 CLAUDE.md

`candidates` 중에서 **CLAUDE.md를 둘 가치가 있는 폴더**를 고른다. 파일 수는 출발점일 뿐이다. 실제로 폴더를 열어 아래 중 하나라도 있는지 확인한다.

- 다른 폴더가 기대는 계약(클라이언트, 스키마, 이벤트 형식)
- 이 폴더에서만 쓰는 패턴(핸들러 래퍼, 상태 관리 방식, 쿼리 키 규칙)
- 틀리기 쉬운 전제(단위, 좌표계, 시간대, 서버·클라이언트 경계, 보안 경계)
- 여러 파일에 걸친 데이터 흐름

어느 것도 없는 폴더(단순 컴포넌트 모음, 유틸 몇 개)에는 만들지 않는다. **문서를 위한 문서를 만들지 않는다.**

### 플랫폼별 초점

폴더를 읽을 때 `stack.platform`에 따라 아래 항목을 먼저 확인하고, 하위 CLAUDE.md의 규칙·계약·흐름도 이 항목 위주로 쓴다.

- **웹:** 렌더링(서버·클라이언트 경계, 리렌더 범위, 하이드레이션), 네트워크(요청 위치, 캐시와 무효화, 쿼리 키, 로딩·에러 처리), 상태 관리(단일 출처, 서버 상태와 클라이언트 상태의 구분, URL 상태)
- **앱:** 화면 스택(내비게이터 구조, 화면 간 파라미터 계약, 포커스·이탈 시 처리, 뒤로 가기), 렌더링(목록 가상화, 리렌더 범위), 상태 관리(화면 상태와 전역 상태의 구분, 영속화), 네트워크(오프라인, 재시도, 포그라운드 복귀 시 갱신)
- **React·React Native 공통:** 훅 사용을 함께 본다. 파생 값을 담은 `useState`, 이벤트로 처리할 일을 하는 `useEffect`, 빠진 의존성이나 정리 함수, 여러 컴포넌트에 복사된 상태가 그 폴더에서 반복되면 올바른 방식을 규칙으로 적는다. 코드를 고치지는 않는다.

`stack.platform`이 null이면(서버, 라이브러리) 이 절은 건너뛴다.

쓰는 방법:
- 코드를 실제로 읽고 확인한 것만 적는다. 함수 이름이나 흐름을 추측으로 채우지 않는다.
- 부모 폴더의 CLAUDE.md나 루트에 있는 규칙은 반복하지 않는다.
- 이미 하위 CLAUDE.md가 있으면 코드와 어긋난 부분만 고친다. 사라진 파일·함수를 가리키는 줄은 지우고, 새로 생긴 계약은 추가한다.
- 40줄 안을 목표로 한다.

새로 만들거나 크게 바꾼 하위 문서가 5개를 넘으면, 쓰기 전에 폴더 목록과 각 문서의 주제를 먼저 보여주고 진행한다.

## 4. 확인

```bash
node "${CLAUDE_SKILL_DIR}/scripts/scan.mjs"
```

다시 실행해서 `dangling`과 `unlisted`가 비었는지 확인한다. 루트 줄 수(`claudeMd.root.lines`)가 60을 넘으면 더 내릴 것이 없는지 다시 본다.

## 5. 보고

- 만들거나 고친 CLAUDE.md 목록과 각 문서의 주제 한 줄
- 넣은 규칙과 뺀 규칙. 예: "Tailwind 미사용으로 Tailwind 규칙 제외", "kebab-case 관례를 따라 파일명 규칙 조정", "앱 프로젝트라 화면 스택 규칙 추가"
- 후보였지만 만들지 않은 폴더와 그 이유
- 기존 규칙과 기본값이 충돌해 손대지 않은 곳

## 하지 않을 것

- 사용자가 쓴 기존 규칙을 기본값으로 덮어쓰기
- 컨벤션에 맞춘다고 기존 파일 이름이나 폴더를 옮기기. 그런 작업은 사용자가 요청할 때 `refactor` 플러그인으로 한다
- 코드를 읽지 않고 폴더 이름만 보고 하위 CLAUDE.md 채우기
- 진행 상황이나 할 일을 CLAUDE.md에 적기. 그건 진행 문서의 몫이다
- 커밋하기. 커밋은 사용자나 `git:ship`이 한다
