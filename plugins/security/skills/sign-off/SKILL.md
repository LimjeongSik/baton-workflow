# 보안 감사 통과 기록

security 플러그인은 Claude가 실행하는 `git commit` / `git push`를 훅으로 검사한다. 보안 감사를 통과하지 않은 소스 변경이 담기면 막는다. 이 스킬이 그 통과를 기록한다.

- 통과는 **파일 내용(blob 해시) 단위**로 `<git-dir>/security-audit/passed.json`에 기록된다. 저장소에는 커밋되지 않는다.
- 기록한 뒤에 파일이 바뀌면 그 파일은 다시 감사 대상이 된다. 코드 리뷰를 반영해 파일이 바뀐 경우도 마찬가지다.
- 감사를 마친 변경은 여러 커밋으로 나눠 담아도 된다.
- 문서·에셋·lockfile·`.claude/` 설정은 검사하지 않는다. merge·cherry-pick·revert·rebase 중의 커밋, 원격 브랜치 삭제도 검사하지 않는다.

## 기록해도 되는 조건

아래를 **모두** 만족할 때만 기록한다. 하나라도 어긋나면 기록하지 말고 사용자에게 묻는다.

1. 이번 변경 범위를 `security:audit`(또는 `security:auditor` 에이전트)로 실제로 감사했다.
2. 각 지적의 파일·라인을 직접 읽어서 검증했고, 타당한 것은 반영했다.
3. `critical`이 남아 있지 않다.
4. `high`가 "보류"로 남아 있지 않다. 기각한 `high`는 왜 악용될 수 없는지 코드로 보였다.
5. 시크릿 파일이 이미 추적 중이라는 지적이 없다. 이 경우 키 폐기와 이력 정리는 사용자가 정한다.
6. 반영한 뒤 프로젝트 검사(lint·타입 검사)를 다시 통과했다.

## 기록

```bash
node "${CLAUDE_SKILL_DIR}/scripts/mark-passed.mjs"
```

미커밋 소스 변경과 원격에 없는 커밋의 소스 내용이 기록된다. **기록한 뒤에는 소스를 고치지 않는다.**

### 다시 감사할 때

게이트에 막힌 파일만 다시 감사하면 된다. 예를 들어 코드 리뷰를 반영해 `src/auth.ts`가 바뀌었다면 `security:audit src/auth.ts`로 그 파일만 감사하고, 위 조건을 확인한 뒤 다시 기록한다.

### 감사 생략

감사가 필요 없는 변경(생성된 코드, 포맷만 바뀐 변경 등)이라고 판단하면, **그 이유를 사용자에게 밝히고 동의를 받은 뒤에만** 생략으로 기록한다. 사용자가 "보안 감사 없이 커밋해"라고 직접 요청한 경우도 같다.

```bash
node "${CLAUDE_SKILL_DIR}/scripts/mark-passed.mjs" --skip "포매터 실행 결과만 포함"
```

생략 이유는 기록에 남는다.

## 게이트 끄기

프로젝트의 `.claude/settings.json`의 `env`에 넣는다: `SECURITY_GATE=0`(전체), `SECURITY_GATE_COMMIT=0`, `SECURITY_GATE_PUSH=0`.

## 하지 않을 것

- 감사하지 않았거나 감사가 실패했는데 기록하기
- 게이트를 피하려고 기록하거나 생략 기록 쓰기, 훅이 인식하지 못하게 git 명령을 바꿔 쓰기
- `critical`이나 보류한 `high`를 남긴 채 기록하기
