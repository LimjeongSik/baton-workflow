# 커밋 & 푸시

순서는 **사전 검사 → 테스트 → 보안 감사 → 코드 리뷰 → 커밋 → 푸시**다. 앞 단계를 통과해야 다음 단계로 간다. 테스트를 감사보다 먼저 하는 것은 새로 쓴 테스트 파일도 감사와 리뷰를 받게 하기 위해서다.

**이 스킬을 실행했다는 것은 커밋과 푸시를 승인했다는 뜻이다.** 단계마다 확인받지 않고 진행하되, 맨 아래 "하드 스톱"에 해당하면 멈추고 묻는다. 인자로 `--no-push`를 받으면 커밋까지만 한다.

문서·에셋·도구 설정만 바뀌었으면 3~5단계를 건너뛴다.

## 1. 상태 파악

```bash
git status --short --untracked-files=all
git diff --stat && git diff --cached --stat
git log --oneline -10
```

- 변경이 없으면 그렇게 보고하고 끝낸다.
- `git diff`를 실제로 읽는다. 무엇이 바뀌었는지 모르는 채로 커밋하지 않는다.
- untracked 파일 중 빌드 산출물·로컬 설정·시크릿은 커밋하지 않고, `.gitignore`에 추가할지 제안한다.
- `git log`로 커밋 메시지 관례(언어, 형식, prefix)를 파악한다.
- 이 프로젝트의 작업 방식 프로필(prefs 플러그인이 프로젝트 루트 `learn/learned.md`에 학습해 두고 세션 시작 시 넣는다)이 컨텍스트에 있으면 작업 방식·글쓰기 절을 따른다. `[확정]` 항목은 묻지 않고 기본값으로 따르고, `[추정]` 항목은 다른 근거가 없을 때만 따르고 따랐으면 보고에 밝힌다. 이번 요청과 다르면 요청을 따른다.

## 2. 사전 검사

검사 명령은 `CLAUDE.md`/`AGENTS.md` → `package.json` 스크립트(패키지 매니저는 lockfile로 판단) → 표준 도구 순서로 찾는다. 명령을 지어내지 않는다. 검사 도구가 없으면 보고에 그렇게 적는다.

```bash
<lint> && <typecheck>
```

진행 문서(`docs/PROGRESS.md` 등)가 있는데 이번 변경이 반영되지 않았으면 먼저 갱신한다. `progress:update` 스킬이 있으면 그 스킬을 쓴다.

## 3. 테스트

`test:write` 스킬로 변경 파일의 테스트를 각 폴더의 `__tests__/`에 작성하고 실행한다. 러너가 없으면 스킬이 설치할지 묻는다. 의존성 설치는 사용자가 정할 일이라서 이 질문만은 확인받는다.

- 이번 작업에서 이미 테스트를 작성했고(`feature:build`, `test:write`) 그 뒤로 소스를 고치지 않았으면, 새로 쓰지 않고 전체 테스트만 실행한다.
- `test` 플러그인이 없으면 기존 테스트 스크립트만 실행한다. 스크립트도 없으면 보고에 "테스트 없음"이라고 적는다.
- 사용자가 러너 설치를 거절했으면 테스트 없이 진행하고, 보고에 그렇게 적는다.

## 4. 보안 감사

메인 에이전트는 `security:auditor` 에이전트에게, 서브에이전트는 `security:audit` 스킬로 직접 감사한다. 감사는 지적만 하므로 판단과 수정은 여기서 한다. 지적마다 해당 파일·라인을 읽어 검증하고, 타당한 것만 반영한다. `critical`/`high`를 기각하려면 왜 악용될 수 없는지 코드로 보여야 한다.

반영했으면 2·3단계를 다시 통과시킨다. 그다음 `security:sign-off` 스킬로 통과를 기록한다. 이 기록이 없으면 보안 게이트가 커밋·푸시를 막는다.

`security` 플러그인이 없으면 추적 중인 시크릿 파일과 diff에 들어간 키·토큰 값만이라도 직접 확인한다.

## 5. 코드 리뷰

`review:codex` 스킬로 커밋되지 않은 변경을 리뷰받는다. 지적을 검증·반영하고 통과를 기록하는 일은 스킬이 한다. 이번 작업에서 이미 리뷰를 통과했고 그 뒤로 소스를 고치지 않았으면 건너뛴다. `review` 플러그인이 없으면 보고에 "외부 리뷰 생략"이라고 적는다.

리뷰를 반영해 소스가 바뀌었으면 2·3단계를 다시 통과시키고, **바뀐 파일만 다시 감사한다**(`security:audit <경로>` → `security:sign-off`). 감사 통과는 파일 내용 단위로 기록되기 때문이다. 재감사 때문에 소스가 또 바뀌면 그 파일만 다시 리뷰받는다. 이 왕복은 한 번까지만 하고, 그래도 끝나지 않으면 멈추고 보고한다.

**커밋이나 푸시가 게이트에 막히면** 감사나 리뷰 뒤에 소스가 바뀐 것이다. 막힌 파일을 다시 감사하거나 리뷰받는다. 게이트를 피하려고 명령을 바꿔 쓰거나 생략 기록을 남기지 않는다.

## 6. 커밋

성격이 다른 변경은 나눈다. 기능 구현, 설정 변경, 문서 갱신이 섞여 있으면 커밋 3개로 나누는 식이다.

- 경로를 지정해서 스테이징한다(`git add src/...`). `git add .`은 변경 전체가 한 덩어리일 때만 쓴다.
- 커밋 하나하나가 검사를 통과하는 상태여야 한다.
- 감사·리뷰를 통과한 변경은 나눠서 커밋해도 된다. 나누다가 소스를 고치면 그 파일은 다시 감사·리뷰를 받아야 한다.

메시지는 저장소 관례 → 선호 프로필의 글쓰기 절 순서로 따른다. 둘 다 없으면 Conventional Commits 형식에 한국어로 요약한다.

```
<type>: <50자 이내 요약>

- 변경 내용
```

`type`: `feat` `fix` `docs` `refactor` `style` `test` `chore` `build` `perf`

- 요약에는 한 일보다 **달라지는 점**을 쓴다. `feat: HomeScreen 추가`보다 `feat: 홈 화면에 자산 목록 표시`가 낫다.
- 본문에는 diff에 없는 **판단 근거**를 적는다. 변경이 자명하면 본문을 생략한다.
- Co-Authored-By 같은 attribution은 Claude Code의 현재 설정을 따른다.
- 여러 줄 메시지는 heredoc으로 넘긴다(`git commit -F - <<'EOF'`).

## 7. 푸시

```bash
git push   # upstream이 없으면 git push -u origin <현재 브랜치>
```

기본 브랜치(`main`/`master`)에 있는데 저장소가 PR로 머지하는 흐름이면(`CONTRIBUTING.md`, PR 템플릿, 머지 커밋 이력으로 판단), 푸시 전에 브랜치를 따서 PR로 올릴지 묻는다.

## 8. 보고

커밋마다 짧은 해시와 제목, 푸시한 브랜치, 검사 결과, 테스트 결과(작성한 테스트 파일, 통과/실패 수), 감사·리뷰에서 채택하거나 기각한 지적과 그 근거를 적는다.

**선호 기록:** 이번 작업에서 사용자가 결과를 고치게 했거나, 선택지 중 하나를 골랐거나, 제안을 거절했거나, "앞으로는" 같은 지시를 했거나, 사용자의 행동에서 방식이 드러났다고 판단했고(예: Claude가 만든 결과를 사용자가 직접 같은 방향으로 고침) `prefs:learn` 스킬을 쓸 수 있으면, 그 내용(예: 커밋을 더 나누거나 합치라고 한 것, 메시지를 고치라고 한 것)를 요약해 넘겨 실행한다. 이번 작업에만 해당하는 내용은 넘기지 않는다.

## 하드 스톱

아래에 해당하면 커밋·푸시하지 않고 사용자에게 묻는다.

- 사전 검사 실패
- 테스트 실패. 원인이 소스 버그면 테스트 스킬이 짚은 파일·라인을 확인한 뒤 고칠지 묻는다. 러너 설치·설정이 실패한 경우도 포함한다
- 보안 감사: `critical`이 남음, `high`를 보류함, 시크릿 파일이 이미 추적 중임. 마지막 경우는 `.gitignore`로 해결되지 않고 키 폐기와 이력 정리가 필요하다
- 리뷰: `critical`/`high`를 보류함, 반영한 뒤 검사가 깨짐, codex 실행 실패. 실패는 통과가 아니다. 리뷰 없이 진행할지는 사용자가 정하고, 그러라고 하면 `review:codex`의 "리뷰 생략" 절차로 기록한다
- 원격이 앞서 있어 푸시가 거부됨. pull·rebase 여부는 사용자가 정한다
- force push, 이력 재작성(`rebase -i`, 푸시된 커밋 `--amend`), 태그·브랜치 삭제가 필요함. 요청 없이 하지 않는다

## 하지 않을 것

- `--no-verify` 등으로 검사 우회하기
- 실패한 테스트를 지우거나 `skip`으로 바꿔서 통과시키기
- 다른 도구가 남긴 변경을 확인 없이 함께 커밋하기
- 커밋 메시지에 하지 않은 작업 적기
