# 사용자 선호 기록 (docs/PREFERENCES.md)

선호 문서는 **이 프로젝트에서 사용자가 일하는 방식을 Claude가 작업 전에 읽는 문서**다. 사용자가 같은 수정을 두 번 시키지 않게 하는 것이 목적이다. 세션을 시작할 때 이 플러그인의 훅이 문서 내용을 컨텍스트에 넣는다.

경로는 기본 `docs/PREFERENCES.md`다. 환경 변수 `DOCS_PREFERENCES_PATH`가 있으면 그 경로(저장소 루트 기준)를 쓴다.

- 인자 없음: 이번 세션 대화와 사용자의 행동에서 선호 신호를 찾아 기록한다.
- 기록할 내용: 그 내용을 기록한다. 다른 스킬이 작업을 마치며 넘긴 요약도 이 형태로 들어온다.
- `init`: 문서가 없으면 템플릿으로 만든다.
- `tidy`: 새로 기록하지 않고 아래 "정리 규칙"만 적용한다.

## 무엇을 기록하는가

**기록한다** (사용자가 직접 보여준 것):
- **고친 것:** 결과를 보고 사용자가 바꾸라고 한 것. 예: 목업을 보고 "여백 더 넓게", 구현을 보고 "에러는 토스트 말고 인라인으로"
- **고른 것:** 선택지 중 사용자가 고른 것과 고르지 않은 것. 예: 목업 두 방향 중 밀도 높은 쪽
- **거절한 것:** 제안을 사용자가 거절한 것. 예: 리팩터링 후보 중 "공용 훅으로 빼는 건 하지 마"
- **일반 지시:** "앞으로는", "항상", "이런 건 묻지 말고" 같은 말

**판단해서 기록한다** (사용자가 말하지 않았지만 행동에서 드러난 것). 메인 에이전트가 스스로 판단해 `[추정]`으로 적는다:
- **사용자가 직접 고친 코드:** Claude가 만든 결과를 사용자가 손으로 바꿨다. `git diff`에서 Claude가 쓰지 않은 변경으로 확인한다. 예: 매번 `useEffect` 데이터 로딩을 쿼리 훅으로 바꿔 둠
- **반복되는 요청 형태:** 비슷한 요청을 같은 방식으로 한다. 예: 기능 요청마다 "모바일도 같이 봐줘"를 덧붙임
- **반복되는 반응:** 같은 종류의 질문·보고에 매번 같은 반응을 한다. 예: 세부 선택지를 물으면 매번 "알아서 해" → 그런 선택은 묻지 않고 진행, 긴 보고에 매번 "요약만" → 보고를 짧게
- **매번 건너뛰거나 바로 승인하는 것:** 예: 목업 1안을 수정 없이 계속 승인함, 매번 보안 단계 결과를 읽지 않고 넘김

판단 기준:
- **근거가 되는 행동을 구체적으로 가리킬 수 있어야 한다.** "이런 걸 좋아할 것 같다"는 근거가 아니다. 어느 작업에서 사용자가 무엇을 했는지 적을 수 없으면 기록하지 않는다.
- 한 번의 행동으로는 판단하지 않는다. 같은 방향의 행동이 두 번 이상이거나, 한 번이라도 사용자가 직접 손을 들인 변경(직접 고친 코드)이어야 한다.
- 행동에서 다음 행동을 끌어내 지시문으로 쓴다. 사용자의 성격이나 능력에 대한 평가는 쓰지 않는다.

**기록하지 않는다:**
- 이번 작업에만 해당하는 내용 (특정 화면의 문구, 특정 버그의 수정 방법)
- 근거가 되는 행동을 가리킬 수 없는 짐작
- 진행 상황과 할 일. 그건 진행 문서(`docs/PROGRESS.md`)의 몫이다
- 프로젝트의 모든 코드가 지켜야 하는 규칙 (파일명, 폴더 구조, import 별칭, 검사 명령). 그건 `CLAUDE.md`의 몫이다. 이런 지시를 받았으면 기록하지 않고, `CLAUDE.md`에 넣자고 보고에 적는다 (`context:sync`가 있으면 그 스킬로)
- 시크릿, 개인 정보

애매하면 "다음에 비슷한 작업을 할 때 이 한 줄이 있으면 사용자가 같은 말을 안 해도 되는가"로 판단한다. 아니면 기록하지 않는다.

## 강도

항목마다 강도를 붙인다.

- `[확정]`: 사용자가 일반 지시로 말했거나("앞으로는"), 같은 선택이 서로 다른 작업에서 두 번 이상 나왔다. 다음 작업에서 **묻지 않고 기본값으로 따른다.**
- `[관찰]`: 한 번 고르거나 고친 것. 다음 작업에서 **선택지를 고를 때 먼저 고려하지만**, 다른 근거가 있으면 다르게 가도 된다.
- `[추정]`: 사용자의 행동을 보고 Claude가 판단한 것. 다음 작업에서 **다른 근거가 없을 때만 따르고**, 따랐으면 보고에 "선호 문서의 추정에 따라 ~로 했다"고 한 줄 적는다. 사용자가 틀렸다고 바로잡을 수 있게 하기 위해서다.

올리고 내리는 규칙:
- `[추정]`대로 했는데 사용자가 그 결과를 고치지 않고 받아들인 작업이 다시 나오면 `[관찰]`로 올린다. 사용자가 그 방향을 직접 고르거나 말하면 그 신호의 강도로 올린다.
- 같은 내용의 `[관찰]`이 다른 작업에서 다시 나오면 `[확정]`으로 올리고 근거 날짜를 더한다.
- 사용자가 반대로 고르거나 `[추정]`대로 한 결과를 고치면, 그 항목을 고치거나 지운다. `[추정]`은 한 번만 어긋나도 지운다.

## 갱신 절차

1. 문서를 읽는다. 없으면 아래 템플릿으로 만든다.
2. 기록할 신호를 모은다. 인자로 받은 내용, 이번 세션 대화에서 위 "기록한다"에 해당하는 것, 그리고 "판단해서 기록한다"에 해당하는 행동. 사용자가 직접 고친 코드는 `git diff`와 이번 세션에서 Claude가 쓴 내용을 비교해 찾는다. 신호가 없으면 문서를 바꾸지 않고 "기록할 선호 없음"이라고 보고하고 끝낸다.
3. 신호마다 절을 정하고, 이미 있는 항목과 비교한다:
   - 같은 내용이 있으면 근거 날짜만 더하고, 다른 작업에서 다시 나온 것이면 `[확정]`으로 올린다.
   - 반대되는 항목이 있으면 **새 신호로 교체한다.** 옛 항목은 지운다. 같은 날 바뀌었으면 사용자의 마지막 말을 따른다.
   - 없으면 추가한다.
4. 상단의 `최종 갱신` 날짜를 오늘로 바꾼다. 오늘 날짜는 `date +%F`로 확인한다.
5. "정리 규칙"을 적용한다.

## 항목 쓰는 법

```
- [확정] 지시문 한 줄. (근거: 2026-10-13 대시보드 목업에서 밀도 높은 안 선택, 2026-10-20 설정 화면에서 다시 선택)
```

- **다음에 할 행동을 지시문으로 쓴다.** "사용자는 미니멀을 좋아함"이 아니라 "카드 그림자 대신 1px 테두리로 면을 나눈다"처럼 그대로 따를 수 있게 쓴다.
- 근거에는 날짜와 어떤 작업에서 무엇을 고르거나 고쳤는지 짧게 쓴다. 근거 날짜는 최근 3개까지만 둔다.
- 사용자가 한 말에 핵심 표현이 있으면 따옴표로 짧게 남긴다. 예: `"설명은 표 하나로"`.

## 정리 규칙 (갱신할 때마다 적용)

- 문서 전체는 **80줄 안**, 절 하나는 **항목 10개 안**으로 유지한다. 세션마다 컨텍스트에 들어가기 때문이다.
- 비슷한 항목은 하나로 합친다.
- 넘치면 근거가 가장 오래된 `[추정]`, 그다음 `[관찰]` 순서로 지운다. `[확정]`은 사용자가 뒤집을 때만 지운다.
- 이미 `CLAUDE.md`에 규칙으로 들어간 항목은 지운다.
- 절 6개는 고정이다. 내용이 없으면 `- 없음`이라고 적는다.

## 템플릿

```markdown
# 작업 방식 선호

> 이 프로젝트에서 사용자가 고르거나 고쳐 준 방식이다. 작업 전에 읽고 따른다. `prefs:learn` 스킬로 갱신한다.
> [확정]은 묻지 않고 기본값으로 따르고, [관찰]은 선택지를 고를 때 먼저 고려하고, [추정]은 다른 근거가 없을 때만 따르고 보고에 밝힌다. 이번 요청이 이 문서와 다르면 요청을 따른다.
> 최종 갱신: YYYY-MM-DD

## 공통 (소통·보고·질문)

## UI·디자인

## 기능 구현

## 테스트

## 리팩터링

## 커밋·리뷰
```

**공통** 절에는 작업 종류와 상관없는 것을 둔다. 예: 보고 길이와 형식, 어떤 결정은 묻지 말고 진행할지, 설명 언어.

## 마칠 때

추가·변경·삭제한 항목을 한 줄씩 보고한다. 새로 적은 `[추정]`은 근거가 된 행동과 함께 보고해서, 사용자가 틀린 판단을 바로 지울 수 있게 한다. 예: "UI·디자인: [관찰] 강조색 하나만 → [확정]", "공통: 보고를 표 하나로 추가". `CLAUDE.md`로 옮기자고 판단한 지시가 있으면 함께 적는다. 커밋은 하지 않는다.

## 하지 않을 것

- 근거가 되는 행동 없이 짐작으로 기록하기
- Claude가 판단한 것을 `[추정]`보다 높은 강도로 기록하기
- 이번 작업에만 해당하는 내용 기록하기
- 한 번 고른 것을 `[확정]`으로 기록하기 (일반 지시였을 때는 예외)
- 뒤집힌 선호를 옛 항목과 함께 남겨 두기
- 절 추가·삭제·순서 변경
