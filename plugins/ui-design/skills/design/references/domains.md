# 분야별 디자인 기준

분야마다 "잘 된 디자인"의 기준이 다르다. 마케팅 페이지의 기준을 대시보드에 쓰면 쓸모없는 화면이 되고, 반대로 하면 지루한 화면이 된다.
각 절은 **필수 요소**와 **이 분야에서 특히 자주 나오는 AI 티**로 나뉜다.

---

## 대시보드·관리 도구·데이터 화면

사용자는 매일 같은 화면을 오래 본다. 목표는 감탄이 아니라 **빠른 판단과 적은 피로**다. 디자인의 개성은 장식이 아니라 정보 위계, 밀도, 타이포, 데이터 색에서 나온다.

**필수**
- 첫 화면에서 "지금 무엇을 해야 하는가"가 보여야 한다. 지표는 행동으로 이어질 때만 크게 보인다. 비교 기준(전주 대비, 목표 대비)이 없는 숫자는 크게 쓰지 않는다.
- 표가 주인공이다. 숫자는 오른쪽 정렬과 `tabular-nums`(고정폭 숫자), 텍스트는 왼쪽 정렬로 둔다. 행 높이는 밀도 옵션을 고려해 잡고, 헤더 고정, 정렬·필터 상태를 표시한다.
- 필터·기간 선택·검색은 위치를 고정하고, 현재 적용된 조건이 늘 보이게 한다.
- 상태색(정상·경고·오류·대기)은 주조색과 겹치지 않는 별도 체계로 두고, 색만으로 구분하지 않는다 (아이콘·텍스트를 같이 쓴다).
- 차트는 질문 하나에 답하게 만든다. 축 레이블과 단위를 쓰고, 범주색은 5~6개 이내에서 구분이 잘 되게 한다. 3D, 도넛 남용, 범례만 보고 읽어야 하는 차트는 피한다.
- 빈 데이터, 로딩(스켈레톤은 실제 레이아웃 모양대로), 권한 없음, 오류 상태를 디자인한다.
- 기준 해상도는 1280~1920 폭이다. 좁은 폭에서는 표를 가로 스크롤하거나 열 우선순위로 숨긴다.
- 키보드로 주요 동작을 할 수 있어야 하고, 포커스가 보여야 한다.

**이 분야의 AI 티**
- 화면 위에 똑같은 KPI 카드 4개 (큰 숫자 + 작은 라벨 + 초록/빨강 화살표 + 스파크라인)
- 네이비 사이드바와 다크 배경, 형광색 차트
- 모든 블록을 같은 둥근 카드와 같은 그림자로 감싸기. 표나 차트는 카드 없이 면 분할만으로도 충분하다
- 의미 없는 그라데이션 차트 채우기, 장식용 아바타 더미
- "Welcome back, John 👋" 인사 헤더

## 모바일 앱

손 안에서, 한 손으로, 짧게 끊어 쓴다. 목표는 **엄지로 빠르게 끝내는 흐름**이다.

**필수**
- 플랫폼 관례를 존중한다. iOS(HIG)와 Android(Material)의 내비게이션, 뒤로 가기, 시트, 스와이프 동작을 따른다. 크로스플랫폼이면 둘이 충돌하는 지점을 의식적으로 정한다.
- 주요 행동은 엄지가 닿는 아래쪽에 둔다. 터치 타깃은 44pt(iOS) / 48dp(Android) 이상으로 잡는다.
- Safe area, 노치, 홈 인디케이터, 키보드가 올라왔을 때의 레이아웃을 처리한다.
- 작은 화면(375pt 이하)과 큰 글자 설정(Dynamic Type, 폰트 배율)에서 깨지지 않게 한다.
- 시스템 다크 모드를 지원하는 앱이면 라이트와 다크 둘 다 디자인한다. 다크는 라이트를 반전한 것이 아니라 따로 조정한 것이어야 한다.
- 모션은 손동작에 답하는 것만 쓴다 (누름, 끌기, 시트 열림). 화면 진입마다 재생되는 장식 애니메이션은 쓰지 않는다.
- 오프라인, 권한 거부(위치·카메라·알림), 느린 네트워크 상태를 디자인한다.

**이 분야의 AI 티**
- 모든 화면 상단의 거대한 그라데이션 헤더
- 카드 안에 카드, 화면 전체가 둥근 카드 목록
- 아이콘마다 파스텔 원형 배경을 깔기
- 웹 랜딩 페이지 같은 구성(히어로 + 기능 3개)을 앱 홈에 그대로 쓰기
- 탭바 아이콘이 의미 없이 모두 같은 무게, 선택 상태가 색만으로 구분됨

## 웹 앱 (SaaS 제품 화면, 업무 도구)

사용자는 일을 하러 왔다. 목표는 **흐름이 막히지 않는 것**이다.

**필수**
- 내비게이션 구조와 현재 위치가 늘 분명해야 한다. 같은 행동은 어디서나 같은 이름과 같은 위치에 둔다.
- 폼: 라벨은 입력창 위에 두고(플레이스홀더를 라벨 대신 쓰지 않는다), 오류는 해당 필드 옆에 무엇을 고치면 되는지 적는다. 저장 상태를 보여준다.
- 주요 행동은 화면당 하나만 강조한다. 파괴적 행동은 시각적으로 구분하고 확인 단계를 둔다.
- 빈 상태는 다음 행동으로 안내하고, 오류는 원인과 해결 방법을 쓴다.
- 밀도는 사용 빈도에 맞춘다. 매일 쓰는 화면은 촘촘하게, 가끔 쓰는 설정 화면은 여유 있게 만든다.

**이 분야의 AI 티**
- 설정 화면까지 카드 그리드로 만들기
- 모든 버튼에 아이콘과 `→` 붙이기
- 기능과 관계없는 일러스트를 빈 상태마다 넣기
- 사이드바 메뉴 옆에 의미 없는 배지와 "New" 태그

## 마케팅·랜딩 웹

처음 온 사람에게 **이게 무엇이고 왜 나에게 필요한지**를 몇 초 안에 전한다. 개성을 가장 크게 드러내도 되는 분야다.

**필수**
- 히어로에는 이 주제의 세계에서 가장 특징적인 것을 둔다 (frontend-design 원칙). 실제 제품 화면, 실물 사진, 작동하는 데모, 강한 타이포 중 이 주제에 맞는 것을 고른다.
- 섹션 순서는 방문자의 질문 순서를 따른다: 무엇인가 → 나에게 무슨 이득인가 → 믿을 수 있는가 → 얼마이고 어떻게 시작하는가.
- 신뢰 요소는 실제 정보로 채운다 (실제 고객, 실제 수치, 실제 후기). 없으면 지어내지 말고 빈자리로 표시한다.
- 성능을 고려한다: 웹폰트는 1~2종으로 두고 `font-display`를 지정한다. 큰 이미지는 최적화하고, 첫 화면 레이아웃이 밀리지 않게 한다.
- 모바일에서 히어로 문구와 주요 행동이 첫 화면에 보여야 한다.

**이 분야의 AI 티**
- 보라·파랑 그라데이션 블롭 배경과 가운데 정렬 헤드라인, 그 아래 "Get started →" 버튼 두 개
- 아이콘 + 제목 + 두 줄 설명으로 된 기능 카드 3개 또는 6개
- 회색 로고 줄 "Trusted by", 근거 없는 "10x faster"
- 섹션마다 아래에서 떠오르는 페이드 인
- 헤드라인에서 한 단어만 다른 색이나 이탤릭으로 강조

## 커머스

**필수**
- 상품 이미지가 주인공이다. UI는 이미지를 방해하지 않게 한 걸음 물러선다.
- 가격, 할인, 배송비, 재고, 옵션 선택 상태가 한눈에 분명해야 한다. 최종 결제 금액이 갑자기 바뀌지 않게 한다.
- 장바구니와 결제 흐름은 단계와 남은 단계를 보여준다. 입력 필드는 최소로 둔다.
- 신뢰는 실제 정보(교환·환불 정책, 실제 리뷰, 사업자 정보)로 만든다.

**이 분야의 AI 티**
- 모든 상품 카드에 같은 그림자와 호버 시 떠오르는 효과
- 근거 없는 "Best seller" 배지 남발, 가짜 별점

## 콘텐츠·문서·에디토리얼

**필수**
- 읽기가 전부다. 본문 줄 길이 45~75자, 넉넉한 행간, 분명한 제목 위계를 둔다.
- 긴 문서는 목차, 현재 위치 표시, 앵커 링크를 둔다.
- 코드 블록, 표, 인용, 이미지 캡션의 스타일을 본문과 조화시킨다.

**이 분야의 AI 티**
- 본문까지 카드에 넣기
- 모든 소제목 위에 대문자 eyebrow 라벨
- 의미 없는 번호 매기기 (`01 / 02 / 03`)
